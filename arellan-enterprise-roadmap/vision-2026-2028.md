# Visión Estratégica 2026-2028

## El Problema que Resolvemos

La Clínica Automotriz Arellan Hnos operaba con tres vectores activos de fraude interno que causaban pérdidas estimadas de S/.2,000-5,000 mensuales:

1. **Cobros por Yape personal:** Un empleado mostraba su QR personal a clientes, desviando pagos fuera del sistema contable del taller
2. **Comisiones ocultas en importaciones:** El mismo empleado negociaba con proveedores extranjeros cobrando comisiones del 20-30% sin declararlas
3. **Uso no autorizado de vehículos:** Vehículos del taller usados para fines personales fuera del horario laboral

## La Solución: Un Sistema que No Permite el Fraude

El ecosistema digital Arellan no solo detecta el fraude — lo hace **imposible** desde el diseño:

```
SIN EL SISTEMA:
  Cliente → paga a quien le presentan el QR → dinero puede ir a cualquier lado
  
CON EL SISTEMA:
  Cliente → paga al QR dinámico del sistema → dinero va directamente al banco corporativo
  El mecánico nunca toca el dinero
  Cada transacción tiene un audit trail inmutable
```

## Pilares de la Visión

### 1. Zero Trust Interno

Ningún empleado es confiado por defecto. Cada acción que muta datos queda registrada en `audit_logs` de forma inmutable — incluyendo quién, cuándo, desde dónde y qué cambió.

```
Principio: "Verificar antes de confiar, siempre"
Implementación: audit_logs, RBAC, MFA obligatorio para roles críticos
```

### 2. Trazabilidad Total del Dinero

Desde que un cliente paga hasta que el dinero aparece en la cuenta bancaria corporativa, existe un trail de eventos verificable en el sistema. No hay huecos donde el dinero "desaparece".

```
Pago cliente (QR) → webhook confirmado → transacción en BD → cierre de caja → extracto bancario
Cada paso verificable. Cada diferencia alertada.
```

### 3. Decisiones con Evidencia

Los owners (Edgar y Juan) toman decisiones basadas en datos reales del sistema, no en reportes manuales que pueden ser manipulados.

```
Dashboard móvil en tiempo real → aprobaciones digitales con biometría → audit trail
Los owners pueden estar fuera del taller y tener control total
```

### 4. Arquitectura que Escala

El sistema está construido para crecer con el negocio sin necesidad de reescritura:

```
MVP: 1 taller, 8 usuarios, 100 OTs/mes
Fase 3: 1 taller, 20 usuarios, 500 OTs/mes
Fase 6: N talleres, SaaS multi-tenant, miles de OTs/mes
```

## Principios de Diseño No Negociables

1. **El audit log nunca se puede modificar ni eliminar** — evidencia forense permanente
2. **Ningún pago puede procesarse fuera del sistema** — QR dinámico obligatorio
3. **MFA obligatorio para roles críticos** — ni el owner puede saltárselo
4. **El mecánico nunca ve datos del cliente** — solo placa y modelo
5. **Cualquier gasto > S/.500 requiere aprobación push del owner** — no hay excepciones
